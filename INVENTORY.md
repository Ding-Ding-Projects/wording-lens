# Wording Lens feature inventory

This is the hand-written, fail-closed inventory for the Wording Lens desktop
application and its documentation surfaces. It is intentionally explicit: a
feature is not considered complete because a similarly named implementation,
test, or capture exists elsewhere. Every row must point to the implementation,
localized copy, persistence path when needed, documentation, focused test,
real built-application interaction, and real capture evidence before the row
can move to `Complete`.

## Baseline and status vocabulary

- Baseline commit: `27750632fdac7f5c000e1120e8f2e4c81518b942`.
- Baseline state: foundation only. No desktop runtime, packaged build, test
  suite, release, documentation deployment, or runtime capture is available at
  this baseline.
- `Pending implementation` means the product code is not present or has not
  been proven in the foundation baseline.
- `Pending evidence` means the implementation may exist in a later task, but
  the required focused test, built interaction, or capture has not been
  supplied to this inventory.
- `Complete` is reserved for a row with all required links and independently
  verified evidence. A blank, guessed, or filename-only reference is invalid.

## Evidence acceptance rule

The inventory must stay red until a later task supplies real file paths,
test names and counts, exact source and packaged-build identifiers, and
captures produced from the built application through the approved isolated
Windows route. A source preview, design mock, guessed URL, stale image,
filename-only manifest, or a test that injects the production boundary is not
evidence. Every future implementation change must update this file and the
relevant article in the same task.
